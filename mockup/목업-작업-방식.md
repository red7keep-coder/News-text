# 목업 작업 방식

웹 페이지는 **목업으로 먼저 보고, 확인받은 뒤에 배포한다.** 이 문서는 그 순서와 규칙이다.
Claude 는 페이지 · 디자인 작업을 시작하기 전에 이 문서를 읽는다.

## 1. 왜 이렇게 하나

- 배포한 뒤에 고치면 방문자가 덜 된 화면을 본다. 그래서 폰에서 먼저 보고 고친다.
- **목업은 실제 페이지를 만드는 코드로 그린다.** 손으로 그린 시안을 따로 두면 실제 페이지와 금방 어긋나고, 같은 일을 두 번 하게 된다.

## 2. 순서

1. **목업 만들기**: 실제 렌더러로 `mockup/output/<기능>/mock_<이름>.html` 을 만든다.
2. **N 표시 · 주소 알리기**: 바뀐 목업에 N 을 붙이고, 사람에게 목록 주소와 바꾼 것 한 줄을 알린다.
3. **사람이 폰 · 태블릿으로 확인**: 고칠 곳을 말하면 2번으로 돌아간다.
4. **"적용해"를 들으면 반영**: 렌더러 · 공통 디자인에 넣고 커밋한다.
5. **배포는 따로 묻는다**: "적용해"는 배포 허락이 아니다. 배포 직전에 다시 확인받는다.
6. **배포 뒤 정리**: `stages.json` 에서 그 기능을 `plan` → `live` 로 옮긴다.

## 3. 목업 만드는 규칙

- **실제 렌더러를 그대로 쓴다.** 렌더러에 `--mock` 같은 옵션을 두고, 출력 위치만 `mockup/output/` 으로 바꾼다. 목업 전용으로 HTML 을 복사해 고치지 않는다.
- **파일 하나로 열리게 한다.** 공통 CSS · JS 를 HTML 안에 넣어서, 서버 없이 파일만 열어도 실제 화면처럼 보이게 한다.
- **표본 자료로만 그린다.** 목업을 그릴 때 AI 호출, 수집, 배포, DB 쓰기는 하지 않는다. 받아 둔 자료나 직접 만든 표본을 쓴다.
- **기사 본문은 넣지 않는다.** 이 저장소의 원칙(README)과 같다. 목업에는 우리가 쓴 글이나 가짜 표본만 넣는다. 결과물(`mockup/output/`)은 커밋하지 않는다(`.gitignore`).
- **폰 화면 먼저.** 폭 360~430px 에서 맞추고, 큰 화면은 그다음에 본다.

## 4. 목업 보기: 목업 서버

```bash
python mockup/mock_server.py          # 포트 8810 고정
```

- 같은 와이파이의 폰 · 태블릿에서 `http://<맥 이름>.local:8810/` 을 즐겨찾기 해 두면 주소가 바뀌지 않는다.
- 목록은 열 때마다 새로 읽는다. 목업을 다시 그린 뒤에는 새로고침만 하면 된다.
- 서버는 `mockup/output/` 안만 내준다(`.env` · 코드는 안 보임).
- 서버가 이미 켜져 있으면 다시 켜지 않는다. Claude 는 PC 에서 브라우저를 열지 않고 **주소만 알린다**.

## 5. 목록 세 칸: `stages.json`

| 칸 | 무엇 | 누가 옮기나 |
| --- | --- | --- |
| 발행 예정 (`plan`) | 아직 배포 안 된 기능. 기능 이름과 남은 일 한 줄을 적는다 | Claude |
| 발행된 화면 (`live`) | 배포된 기능의 목업. 접혀 있다 | Claude (배포 뒤) |
| 자동 보관 | 어느 표에도 없는 파일. 지우지 않고 자동으로 여기 모인다 | 없음 (자동) |

- 새 목업 묶음을 만들면 **같은 커밋에서** `plan` 에 한 줄을 넣는다.
- 남은 일은 그때그때 고친다. 사람이 목록을 정리하거나 파일을 옮기지 않게 한다.

```json
{"plan": [{"name": "기사 페이지", "todo": "목업 확인 → 렌더러 반영 → 배포(묻고)", "files": ["article/*"]}],
 "live": [{"name": "홈", "files": ["home/*"]}]}
```

## 6. N 표시: 바뀐 목업 알리기

목업을 **만들거나 고칠 때마다** 표시한다.

```bash
python mockup/mock_server.py --new "article/mock_article.html" --note "제목 크기 22 → 20"
```

- 목록 맨 위 `N 새로 바뀐 목업` 에 메모와 함께 모이고, 한 번 열면 사라진다.
- 내용이 그대로인 다시 그리기(아래 7절)에는 붙이지 않는다.
- 사람에게 알릴 때는 목록 주소와 바꾼 것 한 줄만 쓴다.

## 7. 다시 그리기: 목업과 실제 페이지 맞추기

```bash
python mockup/rebuild_mocks.py          # 전부
python mockup/rebuild_mocks.py 기사      # 이름에 '기사'가 든 묶음만
```

- 공통 디자인(공통 CSS · 공통 렌더러)을 고친 뒤에는 반드시 돌린다. 그래야 다른 목업도 같은 모양이 된다.
- 새 목업 묶음을 만들면 `rebuild_mocks.py` 의 `JOBS` 에 한 줄을 추가한다. 여기 없는 목업은 옛 모양으로 남는다.

## 8. 수정 요청을 받을 때

- **짚은 곳만 고친다.** 같은 규칙을 쓰는 다른 자리도 바꾸는 게 좋아 보이면 "○○도 같이 바꿀까요?"라고 한 줄로 제안만 한다.
- **디자인 규칙은 문서에 먼저 적는다.** 글자 크기 · 색 · 여백 같은 규칙은 디자인 가이드라인 문서(예: `doc/디자인-가이드라인.md`)에 적고 코드에 반영한다. 다음 화면도 같은 규칙으로 만든다.
- **크기는 정수 px 로 정한다.** "조금 줄여"라는 요청을 받아도 정확한 값(예: 22 → 20)을 정해서 바꾸고, 바꾼 값을 알린다.
- 여러 수정을 "한 번에 하자"고 하면, 그때는 목록에 적기만 하고 "적용해"를 들었을 때 한꺼번에 반영한다.

## 9. 하지 않는 것

- 확인 없이 배포하지 않는다.
- 목업을 외부 공유 서비스(아티팩트 · 임시 호스팅 등)에 올리지 않는다. 목업은 이 컴퓨터의 목업 서버로만 본다.
- 목업 파일을 지우지 않는다. 안 쓰는 목업은 `stages.json` 에서 빼면 자동 보관으로 간다.
